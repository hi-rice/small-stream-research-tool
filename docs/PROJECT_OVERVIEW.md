# 프로젝트 개요

## 1. 프로젝트의 목적

프로젝트명은 `small-stream-research-tool`이며, 사용자 표시명은 **소하천 데이터 관리**이며 NDMI 표기를 유지한다. Python 패키지명은 small_stream_research_tool이다.

국립재난안전연구원의 소하천 관련 연구업무에서 사용하는 소하천 특성정보와 향후 계측자료를 체계적으로 관리·검수·분석하기 위한 Windows 기반 로컬·오프라인 연구지원 프로그램을 목표로 한다. 다양한 구조의 연구자료를 표준화하고, 출처와 변경이력을 유지하면서 연구용 DB로 구축하여 조회·검수·분석하는 도구다. Excel 정리는 이 과정의 일부이며, 핵심 목적은 연구자가 자료의 근거와 처리 과정을 확인하며 분석에 사용할 수 있도록 하는 것이다.

V1은 소하천 기본정보와 특성정보 DB, QC, 기본 통계·그래프에 집중한다. 계측자료와 연구모형은 이후 버전에서 순차적으로 확장한다. 이 문서는 개발 목표와 범위를 설명하며, 기능이 이미 구현되었음을 뜻하지 않는다. 세부 개발 규칙은 루트의 `AGENTS.md`를 따른다.

## 2. 문제 배경

연구자료는 Excel 중심으로 관리되며 파일마다 다음 차이나 문제가 존재할 수 있다.

- 여러 시트, 여러 행으로 구성된 헤더, 병합 셀
- 서로 다른 컬럼명과 컬럼 순서, 추가 또는 누락 컬럼
- 단위 차이, 결측, 중복
- 자료 간 하천명 차이와 특성값 차이
- 행 정렬 이상 가능성
- 분석과 관계없는 운영정보 포함

특정 Excel 양식 하나에 맞추면 자료 구조가 바뀔 때마다 처리 방식도 바꿔야 한다. 따라서 파일·시트·헤더 구조를 탐색하고 데이터 사전을 기준으로 컬럼과 값을 표준화하는 구조가 필요하다. 자료 간 차이는 검수 대상으로 드러내고, 연구자의 판단과 그 근거를 보존해야 한다.

## 3. 사용자와 사용 방식

주 사용자는 소하천 및 재난안전 연구업무를 수행하는 연구자와 연구지원 인력이다. SQL이나 데이터베이스 내부 구조를 직접 알지 않아도 GUI에서 다음 작업을 수행할 수 있도록 한다.

- 파일 등록과 매핑 확인
- QC 결과 확인과 자료 간 비교 검수
- DB 검색과 데이터 추출
- 분석 실행과 그래프 확인
- 결과 저장

로컬 Windows 환경에서 로컬 계정 기반 사용을 기본으로 하며, V1의 기본 기능 전체는 인터넷 없이 동작해야 한다.

V1은 개인 PC의 로컬 계정으로 현재 작업자를 식별한다. 서버·팀 협업·동시편집·온라인 회원가입·이메일/휴대폰 복구·복잡한 권한 관리는 포함하지 않는다. 사용자가 없으면 최초 사용자 등록 화면으로 연결한다. app_user의 비밀번호는 평문으로 저장하지 않으며 자체 암호화·비밀번호 알고리즘을 만들지 않는다. 검증된 password hashing library를 사용하며 세부 library·알고리즘은 Phase 1A 인증 구현 직전에 확정한다. 이 선택은 Phase 0 또는 DB 컬럼 정의 자체의 차단 사유가 아니다.

로컬 앱 계정은 연구자료에서 가져온 운영 인증정보와 구분한다. app_user는 애플리케이션 인증·작업자 메타데이터이며 연구항목·일반 Export·QC 원본값·로그 대상이 아니다. 연구 Excel의 서비스 Key·비밀번호·IP·CCTV·RTSP·개인 연락처는 기존대로 연구 DB Import에서 제외한다. 계정 비활성화는 과거 이력을 지우지 않는다.

| 화면 | 책임 |
| --- | --- |
| 00 로그인 | AuthService / 최초 사용자 등록 |

## 4. 전체 목표 흐름

로그인 → 홈 → Excel 가져오기 → 컬럼 매핑 → 관리코드 검증 → Import Preview → DB 구축 → QC → 특성정보 보정 → 소하천 조회 → 기초통계/그래프 → 결과 내보내기.

DB 구축은 사용자가 확정한 Import 대상을 등록하는 단계이며 QC까지 끝난 최종 확정 자료라는 뜻이 아니다. 파일 선택·Preview만으로 import_history를 생성하지 않는다. Import 성공과 QC 확인 필요를 분리한다.

향후 계측자료 → 강우/수위/유량 시계열 → 홍수사상 → 연구모형·노모그래프 → 모형 보정·검증으로 확장한다.

## 5. V1 구현 범위

V1은 아래 기능을 단계적으로 구현하는 것을 목표로 한다.

1. 프로젝트 및 로컬 DB 기반 구조
2. 소하천 기본정보 관리
3. 소하천 특성정보 관리
4. 데이터 사전
5. 카테고리 및 단위 관리
6. Excel 파일 등록
7. 다중 시트 처리
8. 다중 행 헤더 및 병합 헤더 구조 탐색
9. 컬럼 자동매핑
10. 미등록/불확실 컬럼 `UNMAPPED` 처리
11. Import Preview
12. 11자리 소하천 관리코드 생성·검증
13. 데이터 표준화
14. DB Import
15. 원본 출처 추적
16. QC
17. 자료 간 비교 검수
18. 대표 특성값 관리
19. 수정·변경이력 관리
20. 소하천 DB 조회 및 검색
21. 기본 기술통계
22. 기본 그래프
23. Excel 결과 Export
24. PNG 그래프 Export
25. Windows 로컬 실행/패키징

파일 등록부터 조회·분석·결과 저장까지 기본 기능 전체가 외부 네트워크 연결에 의존하지 않아야 한다.

로컬 계정·최초 사용자 등록·작업자 추적·현재 사용자 표시를 포함한다. V1 연구 DB는 기존 18개와 app_user를 합한 19개 테이블이다. 진행 중 Import 재개는 연구 DB 밖의 로컬 workspace 파일에 선택 상태를 저장하여 지원한다. 전체 셀을 복제하지 않으며 원본 존재·hash를 확인하고 이동·불일치 때 사용자 재지정을 요구한다.

V1 통계는 유효 N, 결측, 평균, 중앙값, 표준편차, 최소, Q1, Q3, 최대와 지역별 비교다. 그래프는 Histogram, Boxplot, Scatter plot이다. 수치형 항목 선택은 data_dictionary.data_type과 analyzable을 기준으로 동적으로 구성하며 Figma 예시 컬럼을 하드코딩하지 않는다. 결측 집계 대상·통계 정의·QC 포함 정책은 구현 전에 확인하며 연구 threshold는 만들지 않는다.

V1 결과 내보내기는 Excel(소하천 조회 결과·QC 결과·보정/변경 이력·기초통계)과 PNG(그래프)다. PDF는 제외한다. 내부 PK·로그·민감정보·app_user 인증정보는 일반 Export에서 제외한다. 원본 Excel을 덮어쓰지 않으며 내보낸 사용자 파일을 프로그램이 자동 삭제하지 않는다.

## 6. V1에서 구현하지 않는 기능

아래 기능은 V1 대상이 아니다. 향후 확장 가능성을 고려하되, 실제 도입은 후속 단계에서 별도로 범위를 정한다.

- 강우·수위·유량 시계열 DB와 유속 시계열
- 홍수사상 자동 추출
- 강우-유량 노모그래프와 수위-유량 관계식
- 비선형 매개변수 최적화와 민감도 분석의 고급 기능
- 머신러닝/딥러닝과 GIS 분석
- 웹 서비스와 클라우드 DB
- 다중 사용자 동시편집
- 외부 API 의존 기능

이 목록은 향후 모든 기능의 도입을 확정한 것이 아니다. 특히 웹·클라우드·외부 API 기능은 로컬·오프라인 기본 방향과 구분하며, 명시적인 요청 없이 추가하지 않는다.

V1은 팀 초대·실시간 협업·서버 동기화·클라우드·복잡한 권한·GIS 지도·하천 사진·시계열 분석·자동 위험도 판정·과거 분석 결과 공유·PDF Export를 제외한다. 여러 연구자, 중앙 서버/API, PostgreSQL, 팀 데이터·분석 결과 공유, 사용자/권한 확대는 향후 확장 영역이다.

## 7. 핵심 식별자

자료의 기본 연결키는 11자리 소하천 관리코드인 `stream_code`다. 소하천명은 JOIN KEY로 사용하지 않으며, 이름의 차이는 검수 대상으로 다룬다.

`stream_code`와 구성요소는 모두 TEXT로 보존하여 선행 0을 유지한다.

| 구성요소 | 길이 | 저장 형태 |
| --- | --- | --- |
| `province_code` | 2자리 | TEXT |
| `city_county_code` | 3자리 | TEXT |
| `town_code` | 3자리 | TEXT |
| `stream_serial_no` | 3자리 | TEXT |

프로그램은 네 구성요소를 순서대로 연결한 결과가 완성된 11자리 `stream_code`와 일치하는지 검증한다.

## 8. 데이터 관리 철학과 추적성

어떤 자료에서 어떤 값이 들어왔는지, 어떤 문제가 발견되었는지, 연구자가 어떤 판단을 했는지를 추적할 수 있는 것이 데이터 관리의 핵심이다. 자동수정의 양보다 정확성·추적성·재현성을 우선한다.

| 구분 | 의미 |
| --- | --- |
| 원본값 | 원본 자료에서 들어온 값 |
| 표준화값 | 확인된 형식·단위 등의 규칙에 따라 표준화한 값 |
| QC 결과 | 값이나 자료 사이에서 발견한 문제와 검수 상태 |
| 대표값 | 현재 분석에 사용하기로 결정한 특성값 |
| 사용자 보정값 | 연구자가 확인하고 보정한 값 |

이 의미들을 혼합하지 않는다. 원본 Excel을 수정하거나 덮어쓰지 않고, 값이 들어온 파일·시트·행·컬럼과 Import 이력을 추적할 수 있도록 한다. 중요한 값 수정과 대표값 변경에는 변경이력을 유지한다.

확인된 규칙에 따른 형식 정규화와 의미를 바꿀 수 있는 자동수정을 구분한다. 하천명 불일치 수정, 이상치 삭제, 결측값 임의 보간, 서로 다른 자료의 값 자동 교체, 행 밀림 자동 수정과 불명확한 컬럼 의미 추정은 수행하지 않는다.

## 9. 데이터 사전을 통한 표준화

데이터 사전은 Excel 구조가 달라져도 표준항목을 기준으로 자료를 관리하기 위한 기반이다. 컬럼 이름이나 위치만으로 의미를 임의로 확정하지 않는다.

| 새 컬럼의 상태 | 처리 방향 |
| --- | --- |
| 기존 표준항목과 확실히 일치 | 등록된 기준에 따라 자동 또는 확인 후 매핑 |
| 의미가 불확실 | `UNMAPPED`로 유지 |
| 사용자가 의미를 확인 | 데이터 사전 또는 컬럼 별칭에 등록 |
| 이후 같은 형태의 파일을 등록 | 확인·등록된 기준을 이용하여 자동 인식 |

컬럼 별칭은 `column_alias`를 통해 표준항목과 연결한다. 미등록 컬럼은 사용자 확인 전 표준항목으로 자동 등록하지 않는다.

## 10. QC와 자료 간 비교 검수

QC는 문제를 발견하고 연구자에게 보여주는 기능이며, 오류 데이터를 자동 삭제하는 기능이 아니다. 주요 검수 대상은 다음과 같다.

- 관리코드 오류와 중복
- 필수값 누락, 자료형 오류, 결측
- 이름 불일치와 자료 간 특성값 불일치
- 단위 문제, 범위 이상, 이상치
- 행 정렬 이상 의심

이상치는 실제 자연현상일 수 있으므로 발견 자체를 오류 확정이나 삭제 근거로 삼지 않는다. 문제의 심각도와 연구자의 검토 상태를 구분하고, 의미가 달라질 수 있는 수정은 자동 수행하지 않는다. 연구자는 자료 간 차이를 확인한 뒤 보정이나 대표값 선택을 판단하며, 그에 따른 변경은 추적 가능해야 한다.

자동 QC 화면 상태는 data_quality_issue.is_active=1인 issue만 집계한다. 활성 issue가 없으면 ‘정상’, 활성 ERROR는 없고 INFO/WARNING만 있으면 ‘확인 필요’, 활성 ERROR가 하나 이상이면 ‘오류’다. INFO는 정상 severity가 아니다. review_status는 사람의 검토 상태로 별도 유지하며 활성 여부와 혼합하지 않는다. 활성 issue가 없다는 집계는 검사 실행 완료를 증명하지 않으므로 실행 여부 안내와 구분한다.

## 11. 특성정보와 대표값

하나의 소하천과 특성항목에 여러 출처의 서로 다른 값이 존재할 수 있다. 원본 특성값과 현재 분석에 사용할 대표값을 구분하여 관리한다.

| 구분 | 역할 |
| --- | --- |
| `characteristic_value` | 원본 특성값과 이력을 관리하는 기준 데이터(authoritative source of truth) |
| `stream_characteristic` | 하천·항목별 현재 characteristic_value_id를 보관하는 재구축 가능한 참조 캐시; 실제 값 복제 없음 |

`stream_characteristic`은 독립적인 기준 데이터가 아니며 직접 수정하지 않는다. 대표값은 `characteristic_value`를 기준으로 변경하고 변경이력을 기록한 뒤 조회용 캐시를 재구축한다. 출처가 다른 값이 있다는 이유만으로 기존 값을 자동 교체하지 않는다.

UI의 **현재 사용값**은 기존 is_representative로 선택한 값이다. characteristic_value는 원본값과 새로 추가한 보정값을 보존하고, record_history는 보정·선택 변경을 기록하며, stream_characteristic은 현재 사용값의 ID를 보관하고 실제 값은 characteristic_value에서 조회하는 참조 캐시다. 별도 현재값 테이블을 만들지 않는다.

동일 stream_code + dictionary_id에 활성 현재 사용값은 최대 하나다. 새 자료 Import만으로 현재 사용값을 변경하지 않으며 사용자가 명시적으로 선택한다. 선택할 characteristic_value_id에 severity='ERROR' AND is_active=1인 issue가 있으면 지정할 수 없다. 활성 WARNING/INFO는 연구자가 확인한 뒤 명시적으로 지정할 수 있다. review_status 변경만으로 ERROR 차단을 해제하지 않는다. 기존 값을 삭제·덮어쓰지 않고 characteristic_value.is_representative 변경·stream_characteristic 참조 캐시 갱신·record_history 기록을 하나의 업무 transaction으로 처리한다. 어느 단계든 실패하면 전부 rollback하며 자동 선정은 금지한다.

고정 연구 특성 컬럼을 캐시에 하드코딩하지 않는다. 데이터 사전 항목과 선택된 값의 연결로 조회한다.

## 12. 보안과 로컬 운영

연구분석과 직접 관계없는 운영·민감정보는 주 연구 DB(main research DB)에 저장하지 않으며, 일반 Export에서도 제외한다.

- 서비스 Key와 인증·계정정보
- 공인/사설 IP
- CCTV 접속정보와 RTSP URL
- 비밀번호
- 담당자 개인 연락처

V1은 로컬 Windows 환경과 개인 PC 로컬 SQLite 사용을 기본으로 한다. 기본 기능이 외부 API, 클라우드 DB, 웹 서버 또는 인터넷 연결을 요구하지 않도록 한다.

V1 login_id는 Service에서 앞뒤 공백 제거 → 소문자 정규화 → 허용 문자·길이 검증 후 저장한다. 영문자·숫자·점(.)·밑줄(_)·하이픈(-)만 허용하고 내부 공백은 거부한다. 정규화된 길이는 4~50자이며 대소문자만 다른 ID는 동일 계정이다. login_id는 NOT NULL UNIQUE이고 별도 정규화 컬럼은 없다. 이 제한은 display_name·department에 적용하지 않는다.

app_user의 로컬 계정 정보는 애플리케이션 전용 인증 메타데이터로 구분하며 연구자료에서 유입되는 운영 인증정보 금지 원칙의 예외로 일반화하지 않는다.

과거 작업이력의 사용자명은 현재 app_user.display_name을 조회하며 별도 이름 snapshot은 V1에 추가하지 않는다. DB Backup/Restore를 지원하고 Restore 전 자동 안전백업, 성공 후 복원된 현재 DB에 작업이력 기록을 수행한다. UI 설정은 QSettings/local config에 두며 연구 DB와 구분한다.

## 13. 기술적 방향

예정 기술 스택은 다음과 같다. 현재 설치되었거나 설정이 완료되었다고 가정하지 않는다.

| 기술 | 예정 용도 |
| --- | --- |
| Python 3.12 | 프로그램 구현 |
| PySide6 | Windows 데스크톱 GUI |
| SQLite | 로컬 연구 DB |
| pandas | 자료 처리와 기본 통계 |
| openpyxl | Excel 읽기·출력 |
| matplotlib | 그래프와 PNG 출력 |
| pytest | 자동화 테스트 |

자료 읽기, 표준화, 검수, 저장과 분석의 책임을 나누어 향후 분석 방법을 추가할 수 있는 구조를 지향한다. 이 문서에서는 세부 DB 컬럼, 구현 구조나 연구 수식을 확정하지 않는다.

## 15. V1 성공 기준

V1의 성공은 기능 개수보다 다음 작업을 안정적으로 수행할 수 있는지로 판단한다.

- 서로 다른 Excel 자료를 등록할 수 있다.
- 원본을 수정하지 않는다.
- 컬럼을 데이터 사전 기준으로 관리할 수 있다.
- 불명확한 컬럼을 임의로 해석하지 않는다.
- 관리코드를 기준으로 소하천 자료를 연결할 수 있다.
- 오류와 불일치를 QC로 확인할 수 있다.
- 원본 출처를 추적할 수 있다.
- 대표 특성값을 관리할 수 있다.
- 변경이력을 확인할 수 있다.
- DB를 검색·조회할 수 있다.
- 기본 통계와 그래프를 만들 수 있다.
- 결과를 Excel과 PNG로 저장할 수 있다.
- 인터넷 없이 사용할 수 있다.
